# 外放语音打断问题梳理（2026-11-17）

## 1. 目标场景

- 输出：Realtek 主机扬声器（外放）
- 输入：蓝牙耳机 `cc ultimate` 麦克风（入耳式）
- 需要支持：
  1. 说“停”立即停止；
  2. 说“停一下”立即停止；
  3. 直接说另一个任务，取消当前播报并交给 GUI Agent；
  4. 助手不能听到自己的外放而自问自答；
  5. 同一时间只有一个助手声音。

## 2. 核心矛盾

外放时麦克风收到的是混合信号：

```text
麦克风 = 用户声音 + 助手扬声器回声 + 环境噪声
```

实测：

| 信号 | 典型电平 |
|---|---:|
| 外放回声 | 3933–13183 |
| 用户人声 | 3000–4500 |

助手的回声经常比用户本人还大。因此：

- 固定能量阈值：调低会误打断，调高会打不断；
- 自适应能量阈值：只能在句子停顿处勉强工作；
- 声纹：只能在**干净音频**上判断“是不是你”，不能把混合信号分开；
- 短词 ASR：混响/回声下“停”经常转写成空、`Ok` 或别的话。

## 4. 已做过的主要尝试

### 4.1 采集/播放分离（有效）

隐藏 BrowserWindow 只做麦克风采集，主窗口只做 TTS 播放，解决“播放时麦克风归零”。

### 4.2 参考信号 + 相关性（部分有效）

用实际播放的 TTS PCM 与麦克风 PCM 做延迟相关性：

- 高相关 → 回声；
- 低相关 → 可能是用户；
- 中间 → 曾用 700ms 探针确认。

问题：

- 真实蓝牙/混响下相关性在 0.1–0.76 之间漂移；
- 探针会暂停播放，用户听到“停一下又继续”；
- 短“停”在探针确认窗口里经常不够长。

### 4.3 声纹（干净音频有效，混合音频失败）

ERes2Net 本地声纹（sherpa-onnx，38MB）：

| 输入 | score | 结果 |
|---|---:|---|
| 用户干净录音自检 | 0.7446 | 通过 |
| Qwen TTS 原始音频 | 0.1141 / 0.1702 | 拒绝 |
| 外放播放中用户喊“停” | 0.02–0.30 | 全部拒绝 |

结论：声纹模型没问题，但播放中的麦克风信号被助手回声主导，声纹 embedding 变成了“回声的声纹”。

### 4.4 单抽头回声减法（离线有效，真实不足）

按最佳延迟/增益从麦克风 20ms 块中减去播放参考 PCM：

| 输入 | score |
|---|---:|
| 未处理混合音频 | 0.19–0.29 |
| 离线减去回声后的残差 | 0.72 |

但真实外放有混响、延迟抖动、蓝牙处理，单抽头减法减不干净；在线声纹仍只有 0.05–0.30。

### 4.5 停止语义（已基本解决）

- bare stop：`停/停下/停止/暂停/停一下/停一停/先停/别说了/不要说了`；
- 任何确认 barge：取消当前响应 + 麦克风静音 900ms + 暂停 GUI 任务 + 2s 内抑制模型回复；
- ASR 空字符串也按 stop 处理；
- 不再把打断语音送 ASR，避免延迟后生成“好的，请问…”。

## 5. 为什么声纹不是答案

声纹回答的是：

```text
这段音频是不是 enrolled 用户的声音？
```

它不回答：

```text
这段混合音频里，哪些是用户、哪些是回声？
```

在回声比人声还大的情况下，直接对混合信号做声纹必然失败。声纹只能作为 **AEC 之后的第二道门**。

## 6. 推荐的正确架构

```text
TTS 播放 PCM（远端参考） ──┐
                            ├─> AEC（自适应回声消除）
麦克风 PCM ─────────────────┘
        │
        ├─> VAD
        ├─> 本地关键词检测（停 / 停一下 / 别说了）
        │       └─> 立即停止 TTS + 暂停任务 + 静音 1s
        └─> ASR（只对近端语音）
                └─> 新任务 → 取消 TTS → Controller 执行
```

要点：

1. **AEC 是核心**：WebRTC AEC3 / speexdsp / 自适应 NLMS，输入麦克风 + TTS 参考 PCM；
2. **“停”用本地 KWS**：不要走完整 ASR/声纹，目标 100–300ms；
3. **新任务用 ASR**：AEC 后的近端语音再转写，避免把助手自己的话当任务；
4. **声纹可选**：AEC 后作为第二道门，过滤其他人声/残留回声；
5. 永远保留 `Ctrl+Alt+X` / 界面“打断”兜底。

## 7. 方案对比

| 方案 | 可靠性 | 工程量 | 适用 |
|---|---|---|---|
| AEC + 本地 KWS + ASR | 高 | 中–大 | 产品化 |
| Duck + ASR（检测人声压低 TTS 再识别） | 中 | 中 | 快速原型，有音量起伏 |
| 声纹直接判混合音频 | 低 | 已尝试，失败 | 不建议继续 |
| 带杆/指向性麦克风 | 最高 | 买硬件 | 演示最快 |
| 耳机模式 + Ctrl+Alt+X | 高 | 0 | 当前兜底 |

## 8. 建议的验收指标

| 指标 | 目标 |
|---|---|
| “停/停一下”打断延迟 | < 500ms |
| 误打断（助手自己声音） | 0 次/10 分钟 |
| 外放回声抑制（ERLE） | > 15dB |
| 新任务语音识别 | 关键指令可正确转写 |
| 长语音 | 25s 内不截断 |
| 蓝牙输出 | 连续播放无咔哒 |
